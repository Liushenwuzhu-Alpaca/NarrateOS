# ADR-0003: 结构化输出重试契约与单仓排他锁

- **状态**: 已采纳 (Accepted)
- **日期**: 2026-11-16

## 背景与问题

1. `Librarian`、`Planner`、`Fact Checker` 与 `Extractor` 均在零 `tools` 的净室请求下工作，跨模型厂商时 `response_format` / `tool_choice` 行为并不统一，模型偶发输出非标准 JSON 或缺字段。
2. 多部作品独立存放于各自 `books/<slug>/` Git 子仓，若同一部作品同时被 CLI、Web 面板或崩溃残留进程写入，会破坏 WAL 状态机与 Git 提交一致性。

## 决策

1. **结构化 JSON 校验与指数退避重试**：要求模型在 fenced JSON 块中输出结构化结果，由 `packages/core` 抽取并以 `zod` 严格校验；校验或解析失败时，将具体校验错误附带进同轮修复提示词自动重试，默认**上限 5 次**，退避间隔为 **`1s -> 2s -> 4s -> 8s -> 16s`**（该上限与退避序列支持通过配置覆盖，测试环境可设为 `0ms`）。超出上限仍失败则抛出结构化异常触发安全中止或人工介入。
2. **单仓排他锁与任意 `bookRoot`**：`BookStore` 与 `NarrativeEngine` 接受任意外部传入的独立 `bookRoot` 路径，在所有写事务与引擎步进前获取 `.ops/tx.lock` 文件排他锁，防止并发损坏 WAL 与 Git 树。

## 取舍与后果

- **收益**：不依赖特定厂商的结构化输出特性即可实现跨模型稳健解析；`.ops/tx.lock` 避免多端同时操作同一作品仓导致状态撕裂。
- **代价**：极端模型畸形输出最多消耗 5 次修复调用与约 31 秒退避总时长，但相比静默吞错或写坏状态文件更安全可控。
