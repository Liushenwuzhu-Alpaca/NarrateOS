# NarrateOS

**把 AI 变成你的专属「长篇小说编辑部」——从一句话脑洞到百万字连载，不吃书、不泄底、不写成 AI 通稿**

## 为什么直接让 AI 写长篇，写不过 10 章就会崩？

用同一个聊天窗口写长篇小说，几乎所有创作者都会在十几章内撞上这三堵墙：

1. **吃书失忆**：第 3 章主角刚断了左臂，第 8 章又潇洒地用左手拔剑；写到第 50 章，出场人物和伏笔一多，早期关键细节早就被挤出了记忆窗。
2. **底牌早泄**：你精心设计了“副会长其实是三年前锁死音乐室的真凶，第 45 章才揭晓”。结果刚把设定喂给 AI，它在第 2 章写副会长出场时，一段心理活动就把谜底全招了——就算你反复叮嘱“千万别剧透”，它也会像憋不住话一样在台词里疯狂明示。
3. **满篇套话与改稿崩盘**：前几章还有活人味，越往后越满篇“眼神中闪过一丝不易察觉的冰冷”；一旦你亲手改了第 12 章的一句台词，后面二十章的剧情就像多米诺骨牌一样全撞了车。

**根本原因只有一个：你让同一个 AI 既当全知编剧、又当当场写手、还要兼任档案管理员。**

**NarrateOS**（基于 `@deepseek-ai/dsh` 构建）的做法，是把这锅大杂烩拆成一间**职责严格隔离的「文学编辑部」**：有人管档案、有人排戏藏底牌、有人蒙着眼睛只写眼前这一场好戏、有人拿着前文原句逐字对账。

```mermaid
flowchart LR
    A["1. 资料员<br/>翻出本场人物近况与过往原句"] --> B["2. 章节导演<br/>结合大局排戏，把未揭底牌锁回抽屉"]
    B --> C["3. 闭关写手<br/>在零剧透状态下专注写出当场对手戏"]
    C --> D["4. 文风筛子 & 段落修补匠<br/>定点换掉套话段落，不重抽整章好戏"]
    D --> E["5. 审稿员<br/>翻出前文原句逐字核对伤残、道具与知情边界"]
    E --> F["6. 记账员 & 后台整理师<br/>更新人物档案、核销旧日程、提炼跨卷记忆"]
```

## 一部小说在编辑部里是如何诞生与渡劫的？

假设你想写一部悬疑长篇：*“旧校舍四楼的音乐室三年前被副会长亲手锁死。第 1 章男主在雨夜捡到那把黄铜钥匙，而三年前的真相要憋到第 45 章才揭晓。”*

### 第一幕 · 试播集定调：不填几万字问卷，先拍好第 1 章
你带着这一句话走进主对话会客室。**总导演**不会逼你先填满枯燥的世界观表格，而是像剧集制片人一样，陪你敲定第 1 章开场第一分钟的画面（谁在哪儿、手里攥着什么）、给每个角色补上主线之外的私心与误判，并把开篇拆成前几步戏剧台阶。

建好书后，编辑部先为你写出**第 1 章「试播集」**并自动停下等你审阅：
- 人物说话的气口对不对？节奏会不会太赶？
- 你可以直接在稿子上顺手改几句台词，编辑部会自动从定稿里提取你满意的鲜活好句存入样句池，让后面的章节越写越贴你的手癖；如果不满意开局走向，告诉总导演一声就能当场重拍第 1 章。

### 第二幕 · 蒙住写手的眼睛：从根源上消灭“说漏嘴”
连载到第 15 章，男主拿着黄铜钥匙去学生会室试探副会长。怎么写出两人表面客套、暗地试探的张力，又绝不把三年前的真相写漏嘴？
- **资料员**先从档案库里挑出黄铜钥匙的来历、两人前 14 章的交锋原句；
- **章节导演**关起门对照全知底牌排好戏，然后**把“副会长是三年前真凶”的底牌锁回抽屉**，只给写手递过去一张当场表演指令：*“写副会长看见钥匙时捏紧茶杯指节泛白，借校规把话题岔开；男主盯着她的茶杯追问排班表”*；
- **闭关写手**在完全不知道三年前真相、也看不到任何“不要写 X”禁令的状态下动笔。**因为根本不知道谜底，写手绝不可能说漏嘴**，反而能把全部笔力砸在眼前的茶杯、视线和话锋机锋上。

### 第三幕 · 拿着前文原句对账，随时容许你亲手改旧稿
初稿写完，先过一遍**文风筛子**：如果某两段冒出了陈词滥调或重复比喻，**段落修补匠**只定点替换那两段，绝不把整章好戏推倒重来。

接着**审稿员**上场。他不管文笔抒情，只做冷酷的事实对账——而且每挑一处毛病，都必须同时摆出**本章草稿原句**和**前文档案原句**（哪怕想捏造一条莫须有的罪名都会被系统当场拦回）：
- *前文写过副会长极度怕黑，这一场停电了她怎么还能独自留在暗室？* -> 打回修补！
- *这个秘密明明只有男主和死党知道，新出场的学妹怎么会顺嘴提起来？* -> 打回修补！

甚至当你写到第 40 章突然灵感一闪，**亲手打开第 12 章的原稿**，把“钥匙锁进了铁柜”改成了“钥匙当场塞给了死党”——点下「同步修改」后，编辑部不会把你后面的心血全覆盖，而是自动顺藤摸瓜找出第 13 到 40 章里哪几处还在写“撬铁柜”，列成清单交给你：是只定点修补那几段，还是按你的授权重跑受影响的那几章，全由你拍板。

### 第四幕 · 百章换卷不失忆：活人有记忆，旧账不刷屏
写到几十万字时，为什么编辑部不会越跑越慢、被陈年流水账淹没？
- **死党不失忆**：已经揭晓的私密同盟（比如“死党早在第 10 章就知道了男主的底细”），全书只在真源档案里记一处；哪怕男主这一章没出场、全章以死党视角写，系统也会自动把这条共同秘密递给死党，绝不会出现“男主不在场，死党就忘了两人关系”的穿帮。
- **蝴蝶效应实时改道**：如果男主在第 20 章提前掀了反派的据点，或者闭关跳过了一整年，导演在排戏时勾一下受影响的未来事件，章末**后台整理师**就会自动醒来：划掉已经泡汤的旧计划，替还没出局的幕后黑手补上变换手段后的新日程。
- **换卷轻装上阵**：一卷写完开启新地图时，本卷已经填完的伏笔自动封存进卷总表，退场的老校工和旧卷闲置道具自动退入休眠区，不挤占新卷视野；直到第 200 章老校工再次推门返场，资料员看着休眠名片一秒就能把他连同当年的伤疤与往事完整唤醒。

## 你在编辑部里的两个座位

你可以随时在两种工作方式之间无缝切换：

| 入口 | 你在这里做什么 | 常用操作 |
| :--- | :--- | :--- |
| **DSH 主对话**<br/>（总编剧会客室） | 和总导演聊新书脑洞、做第 1 章试播集校准、卷中大改剧情走向，或直接用命令指挥全局 | 切换到 **NarrateOS 创作模式** 直接开聊；或输入 `/narrate-step`（写下一章）、`/narrate-yolo 5`（连写 5 章）、`/narrate-sync`（同步手改稿）、`/narrate-signal <便签>` |
| **Operator Studio**<br/>（`/studio` 浏览器工作台） | 三栏可视化编辑部：左边盯每章 6 道工序的实时进展与思考轨迹，中间读正文/看细纲/亲手改稿，右边翻看随时更新的人物卡、伏笔账本与未来日程 | 顶部一键 **写下一章 / 连写 (YOLO)**；中间切换 **直接改稿 -> 保存并自动同步**；底部输入框随时给下一章导演塞一张微调便签（如 *“下一章让雨停，提前引出巡夜人”*） |

> **引擎与作品物理隔离**：本仓库仅存放通用编辑部引擎与创作模式配置，不捆绑任何具体小说；你创建的每一部作品都是 `books/<书名代号>/` 下一个干干净净的独立 Git 仓库，每一章定稿、每一次档案更新都有完整的版本历史兜底。

## 3 步快速跑起来

### 环境要求
- **Node.js**：`>= 22`（推荐 Node 24）
- **pnpm**：`10.33.0+`
- **Git**：每部作品的章节定稿、状态账本与跨章回滚均基于本地 Git 仓库

### 1. 安装与构建

```bash
pnpm install --frozen-lockfile
pnpm run build
```

### 2. 一键启动本地编辑部沙盒（主对话 + Studio 工作台）

在环境变量或仓库根目录 `.env`（已被 Git 忽略）中配置好模型密钥后，启动隔离开发沙盒：

```bash
# 仅初始化并检查沙盒目录（默认位于 /tmp/narrateos-sandbox）
pnpm run dev:sandbox -- --init-only

# 启动本地服务（可自定义端口，例如 PORT=42893）
PORT=42893 pnpm run dev:sandbox
```

启动后打开终端打印的本地地址：
1. 在 **主对话工作台** 顶部切换到「**NarrateOS 创作模式**」，跟总导演聊一句你的小说脑洞即可开书；
2. 点击左侧导航栏的 **NarrateOS Studio** 图标（或访问 `/studio`），即可坐进可视化编辑部推章、改稿、翻阅设定集或为不同岗位调配模型。

Studio 在推章期间提供 **安全中止**，取消在途模型调用，并在事务收尾后显示作品锁释放。要完成本章后再停，在同一按钮的下拉菜单中选择 **写完本章暂停**。

中止或模型失败后，选择 **原地重试** 可复用已经完成的角色结果，包括修改模型路由后重试；如需更改情节、作品资料或重新生成细纲，选择 **从头重跑当前章**。断点保存在作品本地，不进入 Git。正文已提交但账本尚未更新时，原地重试只补跑状态抽取，不覆盖定稿。

### 3. 运行工程门禁与测试（开发者）

修改引擎源码后，运行一条命令即可串联全包构建、类型检查、仓库规范门禁、预设校验与全量单元测试：

```bash
pnpm run check
```

常用分项命令：

```bash
pnpm run build        # 编译全部 4 个源码包并打包 Studio 前端
pnpm run typecheck    # 全包构建与 TypeScript 类型检查
pnpm run lint         # 运行仓库静态规范检查
pnpm test             # 运行全量单元测试与预设集成测试
ssot check design     # 校验 design/ 下的形式化架构、端口契约与崩溃恢复模型
```

## 仓库与作品地图（开发者速查）

### 引擎仓库结构

```text
.
├── packages/
│   ├── dsh-book-store/          # 作品纯文本数据库：人物/道具档案解析、视角与时间线裁剪、原稿检索、文风筛子与 Git 原子事务
│   ├── dsh-book-tools/          # 编辑部受控工具箱：文件读写围栏、只读配额、内存段落修补、暂存区与各岗位交接门禁
│   ├── dsh-pipeline/            # 生产流水线：单章 6 道工序调度、章末后台整理、手改稿同步、跨章冲突自愈与斜杠命令
│   └── dsh-client-ui-studio/    # Operator Studio 浏览器三栏工作台前端
├── presets/
│   └── dsh-preset-narrateos/    # DSH 顶层创作模式、8 大岗位声明配置 (roles/*.yml & prompts/*.md) 与开书校准技能 (narrate-boot)
├── plugins/craft/               # 可按书选装的叙事手艺插件（潜台词、感官锚定、场景节拍、情绪动机等）
├── design/                      # SSoT 形式化架构图 (C4)、需求不变量、端口契约 (VDM-SL) 与事务恢复模型 (Quint)
└── docs/                        # 深度架构、文风词典、视觉规范与演进计划
```

### 单部作品仓库里有什么（`books/<slug>/`）

每部作品都是一个纯文本（Markdown / YAML / JSONL）Git 仓库，直接用任何编辑器都能打开阅读或手改：
- `manuscripts/`：已定稿的章节正文（`ch_0001.md` 起，全书最高事实真源，支持你随时亲手改稿）。
- `world/`：《作者契约》、导演阶段规划与开篇节拍、写手可见的当前卷舞台态势、文风基线、世界局势、待填伏笔备忘录与世界默认事件表。
- `lore_library/`：按需翻阅的世界观百科词条（支持把未揭秘的高维真相折在词条末尾，对写手自动隐去）。
- `entities/`：角色与唯一关键道具的四段式档案（先天红线 / 当前状态与账本 / 生平大事记 / 近期记忆与说话声纹），以及换卷休眠档案（`cold_archive/`）。
- `index/`：纪元总表、各卷总表（含每卷封存的已填完伏笔）与按卷分片的章节大事卡片。
- `.ops/`：编辑部运行台账（事务锁、滚动声纹样句池、作者微调便签队列、手改冲突报告与每章文风健康度记录）。
