# T0 时序守恒、常识因果与多人知情边界自检清单

在流程 A-2 审阅长纲/设定集，以及第三幕调用 `lock_charter_and_boot` 之前，逐项完成以下核验；任何未闭合项必须在主对话中与作者对齐拍板后再建库。

## 1. 常识因果四问 (Common-Sense Causality Audit)

1. **幕后方动机经济性**：对手或施压方为何采用当前布局，而非更低成本、更直接的常规手段？其行动成本、收益与风险是否与其资源体量匹配？
2. **关键线索物理可达性**：主角及同伴如何通过合乎逻辑的渠道（职业接口、现场物理遗留、人际利益交换）接触到破局线索？严禁依赖无端巧合或天降知情人。
3. **主角不可替代手艺**：当前危局为何必须由主角依靠其具体手艺、软肋或特定关系网撬动，而非交给官方机构或路人一眼看破？
4. **核心配角自主弧线**：除主角外，至少 2-3 名核心配角具备独立于主线之外的私欲、算计或认知盲区，在有限信息下会做出合乎自身利益的合理误判。

## 2. `T0` 既成事实与 `future_horizon_events` 严格分账

逐条审视设定：这是开局前（`story_day <= 0`）已成立的事实、此刻在场状态，还是 `T0` 之后才可能发生的预期动态？
- **在场与既成事实入实体卡**：`entities` 中所有初始条目的 `day` 必须 `<= 0`（任何 `day > 0` 条目都会被 `boot-validation` 直接拦截）。人物此刻持有某关键物品时，须能说明其合法来源。
- **未来预定动态入 `future_horizon_events`**：所有 `story_day > 0` 的外部计划或倒计时大事件统一录入 `future_horizon_events`。
- **`premise` 可证伪与导演联动核销**：每条未来事件的 `premise` 必须写成**可被角色行动或局势变化推翻的具体客观条件**（例如 `"账册副本仍锁在钱庄暗格且查账专员尚未进城"`，绝不能写 `"按原计划推进"`）。连载期系统不按日龄盲目跑整理，而是由每章 `Planner` 核对 `premise` 与时间窗口，一旦事件兑现、前提被击穿或过期，由 `Planner` 在 `yield_outline.impacted_horizon_events` 中点名该 `event_id`，触发章末 `Dreamer` 核销或折入 `Archived WARPED` 并重推后续反制动态。

## 3. 四级信息边界与多人共知秘密（SSOT）

| 可见性标记 (`visibility`) | 业务含义 | 写手 (`Writer`) 可见规则 |
| :--- | :--- | :--- |
| `PUBLIC` | 公开常识、众人皆知的外显状态 | 可见 |
| `SELF_ONLY` | 仅特定知情人掌握的心思、私密持有物、误判或共知秘密 | 仅当 `owner`（缺省为该卡实体自身）包含当前 `pov_character` 时可见 |
| `READER_KNOWN` | 读者已知但场上角色不知的戏剧张力点 | 转为 `[仅读者已知的戏剧张力点]` 提示 |
| `OMNISCIENT_SECRET` | 尚未揭晓的幕后真相与底牌（须放第 2 区并绑定 `slot_key`） | **无条件物理剥离（绝对不可见）** |

- **多人共知秘密唯一真源（`owner: "char_a,char_b"`）**：两人或多方共同知晓的私密约定、隐藏身份或往事，遵循 SSOT **只记在其中一张主关联实体卡的第 2 区**，将 `visibility` 设为 `SELF_ONLY` 并显式填写逗号分隔的 `owner: "char_a,char_b"`。
  - **外键硬门禁**：`owner` 中列出的每一个实体 ID 都必须存在于本次建库的 `entities` 列表中（否则 `boot-validation` 报错拦截）。
  - **跨卡自动挂载**：当 `char_b` 作为本章 `pov_character` 而 `char_a` 未出场时，切片器会自动将该共知条目作为只读跨卡知情记忆挂载到 `char_b` 视图末尾，无需在两张卡上重复抄录。
- **防跨文件泄底**：`OMNISCIENT_SECRET` 与 `SELF_ONLY` 条目的核心秘密原文严禁复制进公开的 `current_arc_envelope` 或 `world_summary`（`validateCleanroomNarrativeFields` 会做跨字段子串扫描拦截）。
